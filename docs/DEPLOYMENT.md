# Deployment guide — Haya Nur

Three pieces, deployed independently:

```
Static React build  ──HTTPS /api/*──▶  Express API (Node)  ──Mongoose──▶  MongoDB Atlas
```

The API and the storefront can both live on Render (`render.yaml` at the repo root),
or the storefront can go on GitHub Pages / Vercel and only the API on Render.

---

## 1. MongoDB Atlas (free M0)

1. Sign up at <https://cloud.mongodb.com> (Google sign-in works), create a **Free / M0**
   cluster in the region closest to Mumbai (AWS `ap-south-1` if offered).
2. **Database Access** → add a user (`hayanur`) with an autogenerated password.
3. **Network Access** → *Allow access from anywhere* (`0.0.0.0/0`) — Render's free tier
   uses rotating egress IPs.
4. **Connect → Drivers → Node.js** → copy the string and append the database name plus
   `authSource=admin`:

   ```
   mongodb+srv://hayanur:<password>@cluster0.xxxxx.mongodb.net/haya-nur?authSource=admin&retryWrites=true&w=majority
   ```

   `authSource=admin` is required, otherwise Atlas rejects the login with
   `bad auth : Authentication failed` even when the credentials are correct.
   URL-encode any of `@ : / ? # [ ] %` that appear in the password.

This value becomes `MONGODB_URI`. It is a secret: dashboard only, never git.

## 2. API on Render

**Blueprint (recommended):** Render → **New + → Blueprint** → pick
`zeeshanshaikh95/haya-nur`. It reads `render.yaml` and creates both services.

Fill these on `haya-nur-api` → Environment:

| Variable | Value |
| `MONGODB_URI` | Atlas connection string from step 1 |
| `ADMIN_EMAIL` | the studio's admin email |
| `ADMIN_PASSWORD` | a strong temporary password (forced to change on first login) |
| `CORS_ORIGINS` | the storefront origin (e.g. `https://haya-nur-web.onrender.com`), comma-separated with `http://localhost:5173` for dev |
| `PUBLIC_SITE_URL` | the storefront URL |

`JWT_SECRET` is generated by Render; `AUTO_SEED=true` bootstraps the admin account and
default settings on boot (idempotent, no catalogue data).

Verify `https://<api>.onrender.com/api/health` returns `{"ok":true}`.

**Uploads:** without object storage, uploaded images live on Render's ephemeral disk and
disappear on redeploy. The seed catalogue ships in `client/public/images`, so the shop
looks complete; move to Cloudinary/S3 before relying on admin uploads in production.

## 3. Storefront

**Option A — Render static site (`haya-nur-web`, created by the blueprint):**
set `VITE_API_URL` to `https://<api>.onrender.com/api` and `VITE_PUBLIC_SITE_URL` to
the site URL, then trigger a redeploy. The SPA rewrite rule is already configured.

**Option B — GitHub Pages:** enable Pages → *GitHub Actions*, add a repository
**variable** `VITE_API_URL` with the API origin, and publish the build. Note Pages on a
**private** repository requires GitHub Pro; otherwise make the repository public or use
Option A.

**Option C — Vercel:** framework preset Vite, root `client`, build
`npm run build --workspace client` from the repo root, output `client/dist`, env
`VITE_API_URL` = API origin. Add a rewrite of `/(.*)` to `/index.html`.

## 4. Post-deploy checklist

- [ ] `/api/health` returns `{"ok":true}`
- [ ] Storefront loads pieces, hero slides and images
- [ ] Admin sign-in works from the live origin (CORS) and forces a password change
- [ ] WhatsApp number set in **Admin → Settings** and an order message opens correctly
- [ ] Announcement text and policies reflect the studio's real terms
- [ ] Placeholder photography replaced with the brand's own images
- [ ] `JWT_SECRET`, admin password and `CORS_ORIGINS` set; no `.env` committed
